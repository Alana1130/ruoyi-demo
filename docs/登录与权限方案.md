# 星旅小程序：登录与权限方案

## 一、现状

- **小程序端**：无登录页。`request.js` 用本地存储的 `travel_user_id`（若无则生成 `guest_`+时间戳）作为身份，每次请求带请求头 `X-User-Id`。
- **后端 /travel**：整类 `@Anonymous`，不校验 Spring Security。通过 `getTravelUserId()` 从请求头 `X-User-Id` 取标识，再 `getOrCreateUser(id)` 得到或创建 `xl_travel_user`，得到当前用户 id。
- **问题**：任何人可伪造 `X-User-Id` 冒充他人；无“登录/登出”概念；无接口级“必须登录”或角色权限。

---

## 二、方案概览

### 1. 登录

- **已实现（推荐）**：**Token 登录**
  - 小程序启动时若无 token 则调用 `POST /travel/auth/login`（可传 `openid` 或留空用游客），后端 `getOrCreateUser` 后生成 token 并存入 Redis（如 7 天有效），返回 `{ token, user }`。
  - 前端将 token 存本地，之后所有请求带 `Authorization: Bearer <token>`。
  - 后端在 `getTravelUserId()` 中优先从 token 解析出 userId；无 token 或无效时再回退到 `X-User-Id`（兼容旧版），或对“需登录”接口直接返回 401。
- **后续可扩展**：微信小程序用 `wx.login` 的 code 换 openid/session_key，后端用 openid 调 `getOrCreateUser(openid)` 再发 token，实现微信账号唯一身份。

### 2. 权限

- **接口分级**
  - **匿名可访问**：目的地/线路列表与详情、攻略列表、搜索、轮播等只读接口。
  - **需登录**：我的、点亮、兑换、发帖、约伴、小世界、消息、收货地址等写操作与个人数据接口。
- **实现方式**：在需要登录的接口里若 `getTravelUserId()` 得到 null（未带有效 token 且未带合法 X-User-Id）则返回 401，前端统一拦截 401 提示“请先登录”并可选跳转登录页或弹窗。
- **可选**：后续若要做“管理员审核”等，可为 `xl_travel_user` 增加角色字段，或与 `sys_user` 关联，在接口内按角色判断是否允许操作。

---

## 三、已实现内容

- **后端**
  - `POST /travel/auth/login`：body 可选 `{ openid }`，不传则用游客身份；返回 `{ token, user }`，token 存 Redis 有效期 7 天。
  - `POST /travel/auth/logout`：请求头带当前 token，使该 token 失效。
  - `getTravelUserId()`：优先从请求头 `Authorization: Bearer <token>` 解析 userId；无 token 或无效时回退到 `X-User-Id` + `getOrCreateUser`（兼容旧版）。
- **前端**
  - `App.vue` 启动时若无 token 则调用 `api.auth.login()` 并保存 token。
  - `request.js`：所有请求自动带 `Authorization: Bearer <token>`（若有）；暴露 `getToken/setToken/clearToken`；收到 401 时清 token 并提示「请先登录」。
  - `api.auth.login()` / `api.auth.logout()`：登录、登出（登出后下次进入会再次自动 login 得到新身份）。

---

## 四、使用说明

- 用户无需在小程序内“点登录”：首次打开自动执行 login 并保存 token，后续请求自动带 token。
- 若需“退出登录”：调用 `POST /travel/auth/logout`（需带当前 token），前端清除本地 token，下次进入会再次自动 login 获得新用户（或后续接微信后同 openid 会得到同一用户）。
